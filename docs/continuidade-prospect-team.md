## 1. O que é

**Prospect Team** (assinatura "dados + time") é um CRM de prospecção B2B **para qualquer nicho**, multi-cliente. É um produto separado da Central Tutts.

- **Prospecção:** acha empresas de um nicho no Google Places e na base da Receita (CNPJ). Depois enriquece com decisores e canais públicos e dá uma nota de A a C.
  - Desde a v69 não há nada de nicho fixo no comportamento (nada de "faz entrega"/autopeças na nota, na IA, nas telas e nos exemplos). Autopeças é só um dos 21 nichos prontos do catálogo.
- **CRM:** funil em Kanban, conversas de WhatsApp, e-mail, tarefas e relatórios.
- **Módulos pagos à parte:**
  - WhatsApp (Z-API);
  - agente de IA de atendimento;
  - e-mail ilimitado.
- **Argos:** assistente de voz e texto (o "segundo cérebro") que responde sobre o comercial, sempre dentro do escopo de quem pergunta.
- **Reuniões por vídeo** (v62): sala própria no lugar do Google Meet, com link público para o lead, sala de espera, gravação, transcrição com nome de quem falou e resumo da IA na ficha.
- **Vendas na rua** (v70): roteiro de visitas do dia a partir dos leads de uma campanha (escolhe os melhores que cabem no dia, ordem que anda menos, hora de chegada, almoço), mandado para o celular do vendedor; check-in, registro da visita (resultado, anotação falada, foto da fachada, próximo passo) que move o funil; painel do gestor.
- **Painel master:** separado do CRM, só com o que é do master (v79). Menu: Visão geral; Comercial (Vendas); Clientes (Clientes, **Financeiro**); Sistema (**Configurações**, Operação, Base CNPJ); e o cartão **CRM de demonstração**. O link "Usar o CRM (Tutts)" saiu do menu (a conta Tutts continua igual; entra-se nela por Clientes, se precisar).
  - **Financeiro** (`/plataforma/financeiro`, substituiu "Consumo e custos"): MRR/ARR, pagantes, ticket, custo, margem, receita de módulos; receita por plano, por módulo/extra e custo por serviço; tabela por cliente com contratado, uso das franquias, bolinhas de configuração (WhatsApp, e-mail, IA, equipe, campanha), mensalidade, custo, margem e situação; planilha CSV; detalhe com receita × custo, franquias, checklist e sugestão de upgrade.
  - **Configurações da plataforma** (`/plataforma/configuracoes`): estado de cada serviço (Z-API, Resend, IA, LiveKit, R2, Groq, OpenAI, Argos, ORS, Places, Serper) com Testar e "Como fazer"; tabela de preços, custos unitários (agora com reuniões, transcrição e GB guardado), contato do site e pedidos da apresentação.
  - **CRM de demonstração**: organização separada `demonstracao=true` ("CRM de demonstração", conta "Nexo Sistemas"), dados fictícios gerados em `apps/api/src/modulos/demonstracao` (3 nichos em Salvador, 150 empresas marcadas `descoberta.empresas.demonstracao`, 99 oportunidades, 5 vendedores fictícios, conversas, 12 reuniões com resumo, roteiro do dia). Fica fora de Clientes/Financeiro e as campanhas dela ficam fora da `v_campanhas_descoberta` (nunca busca no Maps). "Abrir a demonstração" cria na primeira vez; "Recriar os dados" apaga e gera de novo. Dentro dela, faixa amarela com Recriar/Voltar.
- **Organizações e unidades:**

  - a diretoria tem acesso só de leitura;
  - cada pessoa vê a unidade toda ou só a própria base.

## 2. Stack e estrutura

- **Monorepo:** pnpm + turbo. Node 22 ou mais, TypeScript, Biome para lint e formatação, Vitest para testes.
- **apps:**
  - `api` (Express 5);
  - `web` (React 19 + Vite);
  - `site` (institucional);
  - `worker-cnpj`, `worker-descoberta` e `worker-enriquecimento`.
- **packages:**
  - `db` (Postgres e migrations SQL que rodam sozinhas);
  - `shared` (zod, DTOs, AppError);
  - `integrations` (Z-API, IA, Places, Serper, ORS, LiveKit, Asaas…);
  - `queue` (pg-boss);
  - `ui` (design system);
  - `config`.
- **Deploy:**
  - api e workers no **Railway**, com Postgres no próprio Railway;
  - front no **Vercel**;
  - as migrations rodam no pre-deploy da api.
- **IA:** DeepSeek por padrão (`IA_PROVEDOR`). O Argos usa Groq (Whisper) para ouvir e OpenAI (gpt-4o-mini-tts) para falar. O time de IA dos carrosséis usa o **Claude Sonnet 5.5** (`ANTHROPIC_CHAVE`, chave da plataforma, US$ 2/US$ 10 por milhão de tokens).
- **Vídeo:** LiveKit Cloud (SFU com simulcast, dynacast e adaptive stream), porque o Railway não aceita UDP de entrada. A api emite os acessos, recebe o webhook (`/livekit`) e confere as salas a cada 10 s. A gravação padrão é pelo navegador de quem conduz (pedaços de 2 s para a api, montados com ffmpeg num bucket S3/R2). A Groq transcreve cada áudio; a IA da conta resume.
  - Pacotes: `livekit-server-sdk` (api/integrations), `livekit-client` e `@livekit/components-react` (só os hooks; a interface é nossa), `aws4fetch` (bucket).
- **Mapas (vendas na rua):** Leaflet 1.9.4 com o mapa aberto do OpenStreetMap (sem chave). Outro provedor de mapa: `VITE_MAPA_TILES` e `VITE_MAPA_CREDITO` no Vercel. Tempo e caminho pelas ruas: OpenRouteService (matriz + rota, a mesma `ORS_API_KEY`); sem ela, estimativa em linha reta (× 1,35, 24 km/h).

### Padrões de código
- **Multi-conta:**
  - na api, a conta vem só da sessão (`contaSql()`, `comConta()`, `usuarioAtual()`);
  - "só a própria base" usa `donoDaBase()`, `naBase()` e `empresaVisivel()`;
  - SQL que usa `contaSql()` precisa ser montado dentro da requisição (função), nunca numa constante de módulo.
- **Erros:** `AppError` (invalido = 422, naoEncontrado = 404). Corpo da resposta: `{ erro: { codigo, mensagem } }`.
- **Web:** `api<T>(caminho, { metodo, corpo })`. O shared é importado por subcaminho (`@prospeccao/shared/rua`, `/geo`, `/reunioes`…). Telas pesadas (reunião, Na rua) são carregadas sob demanda (`lazy` no `main.tsx`).
- **Biome:**
  - nada de seletor CSS descendente de elemento (`.x span`): use classe própria;
  - chave por índice leva `biome-ignore`;
  - `forEach` não pode retornar valor.
- **Argos:**
  - lê o banco só pelas views do schema `cerebro`, com o papel `cerebro_leitura` e o escopo assinado (v2, com o dono);
  - ele mesmo escreve o SQL, e o validador (`validarSql`) confere antes de rodar.
- **Textos:** tudo em português, para quem usa, sem termos técnicos. Exemplos genéricos de B2B (nada de nicho fixo).

## 4. Máquinas e comandos (PowerShell)

O repositório local é sincronizado com o GitHub (`origin main`). O fluxo de cada versão é sempre o mesmo:

1. Baixo o zip da conversa para a pasta `Downloads`.
2. Atualizo o repositório local.
3. Extraio o zip por cima.
4. Faço o commit e o push.

### Máquina "Pichau"
Pasta do repositório: `C:\Users\Pichau\Downloads\prospeccao\prospeccao`

```powershell
cd "C:\Users\Pichau\Downloads\prospeccao\prospeccao"; git stash; git pull origin main
Expand-Archive -Force "$HOME\Downloads\<arquivo>.zip" .
git add -A; git commit -m "<mensagem>"; git push origin main
```

### Máquina "Tutts"
Pasta do repositório: `C:\Users\Tutts\prospeccao` (clonada em 30/10/2026 com `git clone https://github.com/Leonardodevcloud/prospeccao.git`).

```powershell
cd C:\Users\Tutts\prospeccao; git stash; git pull origin main
Expand-Archive -Force "$HOME\Downloads\<arquivo>.zip" .
git add -A; git commit -m "<mensagem>"; git push origin main
```

### Cuidados
- **Sempre entre na pasta do repositório antes do `Expand-Archive`.** Se não entrar, o zip é extraído na pasta do usuário (já aconteceu na Pichau).
- **Máquina nova:** se a pasta não existir, `cd $HOME; git clone https://github.com/Leonardodevcloud/prospeccao.git`. Se o Git pedir nome/e-mail, `git config --global user.name "..."` e `user.email`.
- **Para achar o repositório numa máquina**, rode:
  ```powershell
  Get-ChildItem $HOME -Directory -Recurse -Depth 3 -Filter .git -Force -ErrorAction SilentlyContinue | Where-Object { Test-Path "$($_.Parent.FullName)\pnpm-workspace.yaml" } | ForEach-Object { $_.Parent.FullName }
  ```
- **Depois do push:**
  - redeploy da **api** no Railway (as migrations rodam no pre-deploy);
  - os workers só precisam de redeploy quando o código deles mudar;
  - o Vercel publica o front sozinho.

### Rodar e testar localmente (opcional)
```powershell
pnpm install
pnpm db:migrate        # precisa de DATABASE_URL
pnpm dev               # sobe tudo em paralelo
pnpm test; pnpm typecheck; pnpm lint
```

## 5. Como continuar numa conversa nova

O ambiente da conversa começa **sem o código**. Escolha uma destas formas de levar o código:

1. **Ligar o repositório do GitHub à conversa** (o melhor). Diga o nome do repositório (`Leonardodevcloud/prospeccao`) e peça para adicionar.
2. **Anexar um zip** do repositório local, sem `node_modules`:
   ```powershell
   cd "C:\Users\Pichau\Downloads\prospeccao\prospeccao"
   git archive -o "$HOME\Downloads\prospeccao-codigo.zip" HEAD
   ```

Peça também para ler este documento e o `claude/pendencias-configuracao-crm.md`. Os dois estão nos docs do projeto "Engenharia reversas".

**Zips cumulativos na conversa nova:** a base do zip passa a ser o commit em que a conversa começar. Peça "zip cumulativo desde o commit X" e diga o hash do `git log -1` na hora.
