API do Prospect Team

Ligue o CRM ao que não é CRM: o formulário do site, o ERP (pedido faturado vira Ganho), a loja virtual, o BI e o resto pelo Make ou Zapier.

É uma API REST com JSON. Todas as rotas começam com:

https://app.prospectteam.com.br/api/v1

Se a sua empresa usa um endereço próprio (crm.suaempresa.com.br), o mesmo caminho funciona nele. A descrição completa em OpenAPI 3.1 importa direto no Postman, Insomnia, Make e Zapier.

Está disponível nos planos Time e Escala. Quem cria as chaves é o administrador, em Gestão › Integrações.

Autenticação

Crie uma chave em Gestão › Integrações › Nova chave e mande no cabeçalho de cada pedido:

Authorization: Bearer pt_live_…

A chave aparece uma vez só (no banco fica só o “hash” dela). Crie uma chave para cada sistema, só com as permissões que ele precisa, e revogue quando não usar mais:

PermissãoO que deixa fazer
leads:criarCriar leads (com deduplicação)
leads:lerListar e ver leads, pessoas e histórico
leads:moverMudar etapa (inclusive ganho e perdido), responsável, valor e próximo passo
atividadesRegistrar contato feito e nota
funil:lerLer funis, etapas e usuários
avisosCriar e apagar avisos (webhooks)

Cada chave enxerga só a unidade em que foi criada. Dá para pôr validade e limitar a alguns endereços IP. Tudo o que a API muda fica na Auditoria com o nome da chave.

Limites e erros

600 chamadas por minuto por chave e 20.000 por dia por empresa. Passou: resposta 429 (no minuto, detalhes.tenteEm diz em quantos segundos). Leads criados contam no limite de leads do plano.

Todo erro vem no mesmo formato, com a mensagem em português para mostrar a quem usa:

{
  "erro": {
    "codigo": "dados_invalidos",
    "mensagem": "Informe o nome da empresa (ou da pessoa).",
    "detalhes": [{ "campo": "empresa", "mensagem": "Informe o nome da empresa (ou da pessoa)." }]
  }
}
StatusQuando
401Sem chave, chave inválida, revogada ou vencida
403A chave não tem a permissão, o IP não é permitido ou o plano não tem a API
404O lead (ou o que for) não existe nesta conta
409Conflito (a Idempotency-Key já foi usada em outro pedido)
422Dados inválidos (veja detalhes)
429Passou do limite

Paginação

As listas vêm em { "dados": [...], "proximo": 48190 }, do mais novo para o mais velho. Para a próxima página, mande depois=48190. Quando proximo vier null, acabou.

Idempotência

Mande o cabeçalho Idempotency-Key (até 120 caracteres, ex.: o número do pedido) nos POST. Se a internet cair e o seu sistema repetir o pedido, a API devolve a mesma resposta da primeira vez (com Idempotent-Replayed: true) em vez de criar dois. Vale por 24 horas.

Criar lead

POST/leads leads:criar

Cria o lead no funil. Se já existe um lead com o mesmo telefone, e-mail ou CNPJ, junta nele: registra o que chegou numa nota e responde 200 com "duplicado": true. Novo: 201.

empresa texto · obrigatório
Nome da empresa (ou da pessoa, se for cliente final).
contato objeto
nome, cargo, telefone, email. Telefone em qualquer formato; o CRM normaliza.
cnpj texto
Com ou sem pontuação.
cidade, uf, site texto
Sem UF, o CRM usa a do DDD do telefone.
etapaId número
Etapa do funil (veja Funis e etapas). Sem ela, entra na primeira etapa do funil principal.
responsavelId número
Quem cuida (veja Usuários). Sem ele, segue o rodízio da equipe.
etiquetas lista de textos
Até 6.
valorMensal número
Potencial em R$ por mês.
origem objeto
Ex.: { "canal": "site", "campanha": "black-friday", "utm_source": "google" }. Aparece na ficha.
nota texto
Vai para o histórico do lead.
campos objeto
Qualquer outro dado (vira nota no lead).

Testar sem chave

Confere o seu JSON com as mesmas regras da API, sem gravar nada.

Listar leads

GET/leads leads:ler

Filtros (todos opcionais): etapaId, responsavelId, atualizadoDesde (data ISO, para sincronizar só o que mudou), busca (parte do nome), telefone, email, cnpj, limite (1 a 100, padrão 50) e depois (paginação).

curl "https://app.prospectteam.com.br/api/v1/leads?atualizadoDesde=2026-11-01T00:00:00-03:00&limite=100" \
  -H "Authorization: Bearer $PT_CHAVE"

Ver um lead

GET/leads/{id} leads:ler

O lead, as pessoas da negociação (pessoas: nome, cargo, telefone, e-mail, se decide) e as últimas 20 atividades (atividades).

Mudar etapa, responsável e dados

PATCH/leads/{id} leads:mover

Mande só o que muda: etapaId, responsavelId (null tira o dono), valorMensal, proximaAcao, proximaAcaoEm, etiquetas e motivo (obrigatório ao mover para uma etapa de perdido). Exemplo: o pedido foi faturado no ERP, então o lead vai para Ganho:

curl -X PATCH https://app.prospectteam.com.br/api/v1/leads/48231 \
  -H "Authorization: Bearer $PT_CHAVE" -H "Content-Type: application/json" \
  -d '{ "etapaId": 10, "valorMensal": 1290 }'

Registrar atividade ou nota

POST/leads/{id}/atividades atividades

tipo: whatsapp, ligacao, email, visita, reuniao ou nota; direcao: enviada ou recebida; texto; e, se quiser, proximaAcao e proximaAcaoEm. Contato feito faz a etapa andar sozinha quando faz sentido (ex.: o lead respondeu).

Funis e etapas

GET/funis funil:ler

Cada funil com as etapas na ordem: id, nome e papel (a_abordar, abordado, respondeu, reuniao, proposta, ganho, perdido). Use o id da etapa no etapaId.

Usuários

GET/usuarios funil:ler

As pessoas da conta (id, nome, email, papel, ativo), para usar no responsavelId.

Formulários do site em 5 minutos

POST/entrada/{chave} sem chave da API

Sem programar: em Gestão › Integrações › Formulários do site, crie um formulário e copie o endereço dele. Ele aceita o envio como vier (JSON ou formulário HTML) de qualquer construtor. No primeiro envio, o CRM aprende os campos e sugere para onde vai cada um; você confere na tela.

  • Elementor: no formulário, Ações após o envio › Webhook › cole o endereço (marque “Dados avançados”).
  • WordPress (Contact Form 7): plugin “CF7 to Webhook” › aba Webhook › cole o endereço.
  • RD Station Marketing: Integrações › Webhooks › gatilho “Conversão” › cole o endereço.
  • Typeform: Connect › Webhooks › Add a webhook › cole o endereço.
  • Google Forms: na planilha de respostas, Extensões › Apps Script, cole o script abaixo e crie o acionador “Ao enviar formulário”.
  • HTML puro: use o endereço no action. Quem envia vê a sua página de obrigado (escolha na tela).
<form action="https://app.prospectteam.com.br/api/v1/entrada/f_SUA_CHAVE" method="post">
  <input name="nome" placeholder="Seu nome" required>
  <input name="whatsapp" placeholder="WhatsApp" required>
  <input name="email" type="email" placeholder="E-mail">
  <!-- contra robôs: fica escondido e vazio -->
  <input name="pt_confirmar" style="display:none" tabindex="-1" autocomplete="off">
  <button>Quero conversar</button>
</form>

Google Forms (Apps Script)

function aoEnviar(e) {
  const dados = {};
  e.response.getItemResponses().forEach((r) => (dados[r.getItem().getTitle()] = r.getResponse()));
  UrlFetchApp.fetch('https://app.prospectteam.com.br/api/v1/entrada/f_SUA_CHAVE', {
    method: 'post',
    contentType: 'application/json',
    payload: JSON.stringify(dados),
  });
}

Quem já é lead (mesmo telefone ou e-mail) não duplica: o envio vira nota no lead. Robôs são barrados pelo campo escondido pt_confirmar e pelo limite de envios por minuto. A resposta é 201 { "recebido": true } (ou a página de obrigado, no formulário HTML).

Avisos (webhooks)

O CRM manda um POST com JSON para o seu endereço (https) na hora em que algo acontece. Crie em Gestão › Integrações › Avisos (ou pela API) e escolha os eventos:

EventoQuando
lead.criadoLead entrou no funil (por qualquer caminho)
lead.etapaMudou de etapa (vem com de, a etapa anterior)
lead.responsavelMudou quem cuida
lead.ganhoFoi para uma etapa de ganho
lead.perdidoFoi para uma etapa de perdido (o motivo vem no lead)
mensagem.recebidaO lead mandou mensagem (WhatsApp ou direct)
reuniao.marcadaReunião marcada com o lead
ligacao.encerradaLigação pelo CRM com o resultado e o resumo da IA

Content-Type: application/json
X-Prospect-Evento: lead.ganho
X-Prospect-Entrega: evt_90412
X-Prospect-Assinatura: t=1793455924,v1=5f1c…

{
  "id": "evt_90412",
  "evento": "lead.ganho",
  "em": "2026-11-03T12:12:04.000Z",
  "contaId": 12,
  "lead": { "id": 48213, "empresa": "Mundo Pet Vilas", "etapa": { "id": 10, "nome": "Ganho", "papel": "ganho" }, … }
}

Responda 2xx em até 10 segundos. Se não, o CRM tenta de novo 6 vezes: 1 min, 5 min, 30 min, 2 h, 6 h e 24 h depois. Cada entrega aparece no histórico da tela, com o corpo e a resposta, e dá para reenviar. Falhando por 3 dias seguidos, o aviso é pausado e os administradores recebem um alerta. Use o id (evt_…) para ignorar repetições.

Conferir a assinatura

O cabeçalho X-Prospect-Assinatura traz t (segundos) e v1: o HMAC-SHA256, em hexadecimal, de <t>.<corpo como chegou> com o segredo do aviso. Confira antes de confiar no que chegou, e recuse t com mais de 5 minutos.

import { createHmac, timingSafeEqual } from 'node:crypto';

function avisoValido(corpoCru, cabecalho, segredo) {
  const { t, v1 } = Object.fromEntries(cabecalho.split(',').map((p) => p.split('=')));
  if (Math.abs(Date.now() / 1000 - Number(t)) > 300) return false;
  const esperado = createHmac('sha256', segredo).update(`${t}.${corpoCru}`).digest('hex');
  return timingSafeEqual(Buffer.from(esperado), Buffer.from(v1));
}
import hmac, hashlib, time

def aviso_valido(corpo_cru: bytes, cabecalho: str, segredo: str) -> bool:
    partes = dict(p.split("=", 1) for p in cabecalho.split(","))
    if abs(time.time() - int(partes["t"])) > 300:
        return False
    esperado = hmac.new(segredo.encode(), f"{partes['t']}.".encode() + corpo_cru, hashlib.sha256).hexdigest()
    return hmac.compare_digest(esperado, partes["v1"])
function aviso_valido(string $corpoCru, string $cabecalho, string $segredo): bool {
  parse_str(str_replace(',', '&', $cabecalho), $p);
  if (abs(time() - (int) $p['t']) > 300) return false;
  $esperado = hash_hmac('sha256', $p['t'] . '.' . $corpoCru, $segredo);
  return hash_equals($esperado, $p['v1']);
}

Avisos pela API

GET/avisos · POST/avisos · DELETE/avisos/{id} avisos

Para sistemas que se inscrevem sozinhos (Make, Zapier, n8n). POST com url (https), eventos e, se quiser, nome. A resposta traz o segredo da assinatura (só nela). O DELETE só apaga avisos criados pela mesma chave; os criados na tela continuam.

Make e Zapier

  • Receber do CRM (lead ganho → planilha, Slack, ERP): no Make, módulo “Webhooks › Custom webhook”; no Zapier, “Webhooks by Zapier › Catch Hook”. Copie o endereço que eles dão e crie um aviso com ele em Gestão › Integrações.
  • Mandar para o CRM (cadastro de outro sistema → lead): módulo “HTTP › Make a request” (Make) ou “Webhooks by Zapier › POST” (Zapier) para /leads, com o cabeçalho Authorization.
  • Importe a descrição OpenAPI para ver todos os campos.
